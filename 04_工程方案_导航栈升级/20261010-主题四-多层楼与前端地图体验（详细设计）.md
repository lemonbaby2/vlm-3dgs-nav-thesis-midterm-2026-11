## 1. 背景与现状（代码级）

### 1.1 已有的楼层/平面数据

| 数据 | 内容 | 现状 |
|---|---|---|
| `ground_levels.json/txt` | 楼层聚类：`level_id / z_median / z_min / z_max / point_count / bbox / stair_like` | 已生成（x_slam 保存/维护）。cf09301：1 个 level，z∈[-0.73, 4.06]，`stair_like=1`（两层被楼梯连成连续 z 带）；cf09281658 类似 |
| `stairs/stair_patches.yaml` | 面片：`patch_id / type(floor/stair_entry/tread/stair_exit) / floor_id / stair_id / flight_id / step_index / mean_z / bbox / reviewed` | 已生成（楼梯工具链）。cf09301：`floor_0` mean_z=2.851、`floor_1` mean_z=5.595、`stair_A` t01~t16 + entry/exit；**当前被质检拒绝**（`stairs.rejected-anchor-20261009`） |
| `stairs/stair_graph.yaml` | 楼梯图：`from_floor_id / to_floor_id / nodes[patch_id] / edges[delta_z_m / horizontal_gap_m / confidence]` | 已生成；cf09301 的 stair_A 连 floor_0 → floor_1（Δz≈2.74m） |
| planner 楼层过滤 | `LoadGroundLevels` + `PathCrossesGroundLevels`（防穿楼板） | 已实现（x_planner_v2） |
| 前端 | Three.js 场景；`/x_nav/global_map` 整图收 + 累加 100 帧；`MapManager` 有分块弹窗 | **无按层加载、无小地图、无图层管理** |

### 1.2 缺口清单

| # | 缺口 | 影响 |
|---|---|---|
| 1 | 没有"按层"的产物（点云/预览/索引） | 前端无法"只看本层" |
| 2 | patch 是平面，不能直接切立体点云；且可能被拒（cf09301 现状） | 需要组合方案 + 降级路径 |
| 3 | 前端无楼层概念（不知道当前层、无切层入口） | 多层体验缺失 |
| 4 | 全局视野只能靠 SLAM 的 600m 窗口，不滚动、不导览 | small map 缺失 |
| 5 | 切图/换层与 `switch_map` 强耦合（会重启 slam/planner） | 误操作会中断导航 |
| 6 | 图层无管理（关键帧/patch/导航点混在一起） | 调试图效率低 |

### 1.3 设计原则（先立规矩）

- **浏览与导航解耦**：前端切层只切**显示文件**；机器人实际定位/导航所在楼层由 SLAM/planner 决定
- **patch 可选，ground_levels 必须**：任何按层功能在 patch 缺失/被拒时都能用 ground_levels 工作
- **产物一次烘焙、多端消费**：levels 产物同时服务前端预览、小地图、主题二瓦片、主题三合并
- **开关默认关**：`frontend_floor_mode=false` 时行为与现状一致

## 2. 目标与不变量

### 2.1 目标

1. **按层产物**：`levels/` 索引 + 每层预览点云（低清），保存/合并/离线三处可生成
2. **只加载本层**：普通预览模式只显示当前楼层；楼梯处显示相邻层过渡
3. **商场式小地图**：角落全局压缩图，朝向可同步，鼠标/列表切层，点击定位
4. **图层系统**：实时点云 / 静态瓦片 / 楼层 / 关键帧 / patch / 导航点开关与点选
5. **零回归**：新功能关闭时与现状一致；切层绝不触发 `switch_map`

### 2.2 不变量（评审重点）

- 前端**只消费数据，不改变机器人**（除显式导航指令）；切层/浏览不影响定位与导航
- 楼层判定以 `ground_levels` 为硬基础；patch 只做增强
- 单层产物与全局产物**版本联动**（`source_pose_version`），过期即失效
- 产物缺失时**逐级降级**：levels → 客户端 z 过滤 → 显示全图（现状）

## 3. 概念速览（正文用到的角色）

| 概念 | 一句话 |
|---|---|
| level / floor | 地面高度层（楼层）；由 ground_levels 聚类得出 |
| patch | 楼板/楼梯踏面等面片（平面），带编号、范围、高度 |
| floor polygon | 楼层面片的水平范围（bbox/多边形） |
| 高度窗口 | 以楼层高度为中心、上下各取一段 z 范围 |
| 预览点云 | 每层低清点云，专门给前端看 |
| 小地图 | 页面角落的全局俯视图（商场导览图） |
| 正交相机 | 没有透视变形的俯视相机（商场图那种"平"的感觉） |
| 视口/scissor | 在一个画布内划出一块区域渲染（角落小地图） |
| Raycast 拾取 | 鼠标点中 3D 物体（用于点楼、点块、点关键帧） |
| ODIN/odom | 机器人实时位姿（用于小地图上的箭头） |

## 4. 设计 A：levels 产物烘焙

### 4.1 核心原理（平面 patch 也能切楼层）

patch 是 2.5D 平面片，**不需要立体 patch**；楼层切分靠三维度组合：

```
本层点云 = ground_levels 给出的楼层高度 z（竖直基准）
         ∩ floor patch 的平面范围（水平范围；无 patch 时用整图）
         ∩ 高度窗口 [z_floor - 0.3m, z_floor + wall_height]（**自适应**：wall_height = story−0.5m，封顶 2.8m，见 A2）
楼梯点   = 归入相邻两层（依据 stair_graph 的 from_floor_id/to_floor_id）
```

- 高度窗口解决"天花板/上层被拉进本层"和"下层地板出现在本层"的问题
- floor polygon 解决"中庭/挑空区域"的水平裁剪（没有楼板的地方不属于本层）
- 墙体落在窗口内，保留（本层预览需要墙）

### 4.2 产物格式（建议）

```
<map>/
  levels/
    index.json                     ← 楼层索引（前端/后端消费）
    <level_id>/
      preview_downsize.pcd         ← 本层低清预览（0.3m，几十 KB）
      full_downsize.pcd            ← 可选：本层全图 0.2~0.3m（P2）
    stairs_<stair_id>.pcd          ← 楼梯过渡层（归相邻两层显示）
```

`levels/index.json`（建议）：

```json
{
  "version": 1,
  "map_id": "cf09301",
  "source_pose_version": 1,
  "wall_height_m": 2.8,
  "z_margin_m": 0.3,
  "generated_at": "2026-10-10T17:00:00",
  "floors": [
    {
      "level_id": 0,
      "z_median": 2.851,
      "z_range": [2.55, 3.15],
      "bbox": {"min_x": -3.93, "min_y": -6.6, "max_x": 7.42, "max_y": 8.0},
      "patch_ids": ["floor_0"],
      "preview": "levels/0/preview_downsize.pcd",
      "point_count": 12345,
      "stairs": [
        {"stair_id": "stair_A", "to_level": 1, "entry_patch": "stair_A_entry",
         "exit_patch": "stair_A_exit", "delta_z_m": 2.744, "reviewed": true}
      ]
    }
  ]
}
```

- `reviewed` 透传自 patch（自动几何门 + 放行策略的结果；前端可标注"未复核/待放行"）
- `stairs` 为空 = 无楼梯语义（cf09301 当前 patch 被拒时，仅用 z 信息）

### 4.3 楼层判定规则（无 patch 降级）

| 数据条件 | 判定方式 |
|---|---|
| 有合格 patch（reviewed=true） | floor patch `mean_z` 为层高；bbox 为水平范围；stair_graph 建楼梯邻接 |
| 只有 ground_levels（cf09301 现状可行） | `z_median` 为层高；水平范围取该 level 点的 bbox；楼梯用 z 突变区（stair_like=1）粗标 |
| 什么都没有 | 客户端 z 直方图找峰做临时楼层（兜底） |

> 注意：cf09301 的 ground_levels 只有 1 个 level（楼梯把两层连成连续 z 带）。因此生成器需要**二级切分**：当 `stair_like=1` 或 z 跨度大于层高阈值时，按 **z 直方图峰值/密度法**切出实际楼层（**实测可行**：bin=0.1m、峰值阈值=20%，两个真图分别切出 2/3 层；**间隙法不可用**——楼梯把楼层连成连续带，见附录 C·A1）。

### 4.4 生成方式

1. **楼层带草稿（在线，属语义流水线）**：建图中 SemanticPipeline 增量维护 `ground_levels.draft.json`（主题一 §4.13）——作为**可用性评估/楼层预警**的输入；**不产出 levels 预览**
2. **levels 预览产物：finalize 烘焙（主路径）+ 旧图 CLI 补算**：主题一 finalize 权威重算楼层并烘焙 `levels/`（与瓦片/nav_light 同批校验）；CLI `semantic_tool levels --map-dir ... [--wall-height 2.8] [--downsample 0.3] --write`
3. **合并后**：主题三统一重烘焙流水线一并重算
4. 输入：`global_map.pcd`（或 surf/ground/obs 逐帧）、`ground_levels`、`stairs/*`（可选）；单遍流式处理（读点 → 判层 → 追加到对应层云），内存峰值 = 单帧 + 各层目标云

### 4.5 与主题二瓦片的关系

| 产物 | 用途 | 体量 |
|---|---|---|
| `levels/<id>/preview_downsize.pcd` | 只显示本层的预览、小地图 | 几十 KB/层 |
| `chunks/<gx>_<gy>/lod1.pcd` | 工作中视图的高清块 | 较大 |
| 多层地图的块级分层（可选） | `chunks/<gx>_<gy>/lod1_f<floor>.pcd` | 双倍存储 |

**建议**：P0 只做 levels 预览（小、稳、立即见效）；块级分层（per-floor tiles）放 P2 按需评估——大图多层时再开启，避免无谓的存储翻倍。

## 5. 设计 B：预览按层加载与切换

### 5.1 两个"楼层"概念（关键设计）

| 概念 | 含义 | 决定者 |
|---|---|---|
| **浏览楼层**（browse floor） | 前端当前展示哪层 | 操作者（点选/自动跟随） |
| **机器人楼层**（robot floor） | 机器人实际在哪层 | SLAM 位姿 + ground_levels 匹配 |

- 默认"跟随模式"：浏览楼层 = 机器人楼层（自动跟随）
- 操作者手动切层 → 进入"自由浏览"模式；机器人换层时提示"是否切回跟随"
- **浏览楼层切换永远不调用 `switch_map`**（这是与现状最关键的解耦）

### 5.2 加载策略

```
浏览楼层 = F
加载：
  F 层：preview_downsize（占位）+ 视口内 chunk 瓦片
  F±1 层（楼梯邻接层）：仅当机器人处于楼梯/过渡区时加载低清（半透明）
  其他层：不加载（内存与带宽省下来）
切换 F：
  1) 卸载旧层对象（BufferGeometry dispose）
  2) 拉新层 preview（命中缓存则直接用）
  3) 视口瓦片按主题二 TileManager 规则加载
  4) 小地图同步高亮新层
```

### 5.3 楼梯过渡与自动换层

- 数据：`stair_graph` 的 `from_floor_id/to_floor_id` + `delta_z`
- 判定机器人"正在上/下楼梯"：位置进入 stair patch 区域（有 patch 时）或 z 在两层之间（无 patch 时）
- 表现：两邻层同时显示（当前层不透明、目标层半透明）+ 楼梯高亮 + 楼层按钮提示
- 完成后自动切换到目标层（跟随模式）

### 5.4 与实时数据的配合

- 实时点云/障碍/机器人模型始终显示（与楼层无关）
- 楼层切换只影响**静态底图**层
- 可在 HUD 显示"机器人楼层 / 浏览楼层"两个标签，避免操作者混淆

## 6. 设计 C：全局压缩小地图（商场导览图）

### 6.1 数据

| 数据 | 来源 | 体量 |
|---|---|---|
| 全图预览 | `global_map_downsize.pcd`（已有） | cf09301：205KB |
| 每层预览 | `levels/<id>/preview_downsize.pcd`（主题四新增） | 几十 KB |
| 机器人位姿 | odom 话题（现有 WS） | 实时 |
| 楼梯图标 | `levels/index.json` 的 `stairs`（位置取 entry/exit 中心） | 元数据 |

### 6.2 渲染

- 位置：页面右下角（或左下角）固定小画布，约 240×240
- 相机：**正交俯视相机**（商场图风格）；支持"北向上"与"机头向上"两种模式（默认北向上，机头向上时地图旋转）
- 主视口与主相机：小地图可同步主相机的 yaw（用户要求"朝向和局部点云同步"→ 提供开关 `minimap_follow_yaw`）
- 机器人：箭头/圆点，来自 odom；朝向随 yaw
- 楼层高亮：当前层以实色渲染，其他层可选淡显或隐藏

### 6.3 交互

| 交互 | 行为 |
|---|---|
| 点击层号列表 | 切换浏览楼层（纯前端） |
| 点击楼层图元（Raycast） | 同上；适合直接点"那栋楼的二层" |
| 点击地图上的位置 | 主视口聚焦该点；可选"下发导航目标"（走现有导航点接口，需确认目标层合法） |
| 悬停 | 显示坐标/楼层/最近关键帧 id（带主题三图层时） |
| 滚轮 | 缩放小地图视野（可选） |
| 点击楼梯图标 | 高亮楼梯 + 提示可切换到相邻层 |

### 6.4 性能

- 小地图只消费 downsize 数据（≤ 几百 KB），加载一次常驻
- 楼层切换只切可见性（`visible=true/false`），不重建场景
- 渲染用一个独立 `WebGLRenderer` 小画布或主 renderer 的 `scissor` 视口（二选一，**待定**；建议先独立画布，简单稳）

## 7. 设计 D：图层系统与交互

### 7.1 图层清单

| 图层 | 数据源 | 默认 | 交互 |
|---|---|---|---|
| 静态底图（当前层） | levels + chunks 瓦片 | 开 | 不可点（背景） |
| 相邻层（过渡） | levels | 自动（楼梯时） | 半透明 |
| 全局小地图 | global downsize + levels | 开 | 见 6.3 |
| 实时点云 | WS `current_pointcloud` | 开 | 可调点大小/颜色 |
| 障碍/导航点 | WS 现有话题 | 开 | 点选显示名称 |
| 关键帧位姿 | `get_keyframe_poses` + `/x_nav/keyframe_graph`（主题三） | 关 | 点选显示 id/位姿；overlap 连线 |
| patch/楼梯 | stair_patches/stair_graph | 关 | 点选显示 `patch_id/step_index/reviewed`；高亮楼梯 |
| 地面层/地面图 | `global_ground_map`（可选） | 关 | 调试用 |

### 7.2 图层管理 UI

- 右侧可折叠"图层"面板（checkbox + 透明度滑条）
- 状态持久化（localStorage）；支持"诊断模式"一键开关键帧+patch
- 与主题五消歧界面共用面板区域（消歧时自动置顶关键帧/候选图层）

### 7.3 拾取信息卡

- 点击关键帧：`global_keyframe_id / map_id / 位姿 / 时间`
- 点击 patch：`patch_id / type / stair_id / step_index / reviewed`
- 点击楼层：`level_id / z_median / 是否楼梯层`
- 信息卡可"复制为命令"（如主题三的 anchor 选择参数）

## 9. 参数设计（yaml/前端配置，默认关闭）

| 参数 | 建议默认 | 说明 |
|---|---|---|
| `frontend_floor_mode` | `false` | 按层加载总开关 |
| `levels_wall_height_m` | 自适应 | 高度窗口上界：`story−0.5m`（cap 2.8m，见附录 C·A2） |
| `levels_z_margin_m` | `0.3` | 高度窗口下界余量 |
| `levels_hist_bin_m` | `0.1` | 二级切分：z 直方图 bin 宽（峰值/密度法） |
| `levels_peak_threshold` | `0.2` | 二级切分：峰值阈值（最大 bin 的 20%） |

## 附录 A：专业名词详解

### A1. level / floor（楼层）
- **是什么**：按高度聚类后地面的"层"。`ground_levels` 里的 `level_id` 就是它。
- **为什么**：多层建筑需要知道"人在哪层"，跨层导航/显示都依赖它。
- **本方案角色**：按层加载与切层的基础；小地图楼层按钮的来源。

### A2. ground_levels
- **是什么**：从 `global_ground_map.pcd` 聚类出的楼层数据（高度、范围、点数、是否含楼梯）。
- **为什么**：最可靠的楼层基准（地面点最稳），也是 planner 楼层过滤的输入。
- **本方案角色**：无 patch 时的唯一楼层依据；有 patch 时用于校验。

### A3. patch（面片）
- **是什么**：楼板/楼梯出入口/踏面等"平面片"，带编号和范围（`patch_id/type/bbox/mean_z`）。
- **为什么**：给地图语义（这是楼梯、这是楼板），跨层导航与质检需要。
- **本方案角色**：floor patch 提供楼层平面范围与高度；stair graph 提供楼梯邻接关系。

### A4. floor polygon（楼层面范围）
- **是什么**：楼板面片的水平覆盖范围（bbox 或多边形）。
- **为什么**：中庭/挑空处没有楼板，只按高度切会把"空"也当本层。
- **本方案角色**：高度窗口 ∩ 平面范围的"平面范围"。

### A5. 高度窗口
- **是什么**：以楼层高度为基准、上下各取固定余量的 z 区间（如 `[z-0.3, z+2.8]`）。
- **为什么**：简单有效地把天花板、上层地板的点排除出本层。
- **本方案角色**：三层组合切分中的"竖直切刀"。

### A6. 预览点云（preview）
- **是什么**：专门为显示生成的每层低清点云（0.3m 降采样）。
- **为什么**：完整层点云太大，预览只需轮廓与主要结构。
- **本方案角色**：按层显示与小地图的基本素材。

### A7. 分层/过渡层（stairs_*.pcd）
- **是什么**：楼梯点云单独成层（或复制进相邻两层）。
- **为什么**：楼梯横跨两层，归任何单层都会"缺一块"。
- **本方案角色**：上下楼时两层联动的过渡显示。

### A8. 正交相机（Orthographic Camera）
- **是什么**：没有近大远小透视变形的相机，像工程图。
- **为什么**：商场导览图/平面图都用它，观感"平"、距离感准确。
- **本方案角色**：小地图默认相机。

### A9. viewport / scissor
- **是什么**：WebGL 的"渲染区域裁剪"：在同一个画布里只渲染一块矩形区域。
- **为什么**：可以在主场景里画一个小地图，省一个 WebGL 上下文。
- **本方案角色**：小地图两种实现之一（另一种是独立小画布）。

### A10. Raycast（射线拾取）
- **是什么**：从鼠标位置向场景发一条射线，求它击中哪个物体。
- **为什么**：点击楼层/关键帧/patch 的前提。
- **本方案角色**：小地图点楼层、主视图点关键帧/瓦片。

### A11. odom（里程计位姿）
- **是什么**：机器人当前估计位置姿态（`/base_link/odom`）。
- **为什么**：小地图上要画"我在哪、朝哪"。
- **本方案角色**：小地图机器人箭头数据源（实时 WS）。

### A12. 浏览楼层 vs 机器人楼层
- **是什么**：前者是"你正在看哪层"，后者是"机器人实际在哪层"。
- **为什么**：操作者会想翻看别层，但导航必须按机器人真实层工作——混淆两者会出事故。
- **本方案角色**：前端 HUD 分开显示；切浏览层不影响导航。

### A13. switch_map
- **是什么**：现有后端接口，切换机器人使用的地图（会重启 slam/planner）。
- **为什么**：导航换图必须走它；但"只是看看别的楼层"绝不能走它。
- **本方案角色**：明确解耦——楼层切换是纯前端行为。

### A14. fallback（降级）
- **是什么**：高级数据不可用时自动使用低一级的数据/行为。
- **本方案角色**：patch 缺失→用 ground_levels；levels 产物缺失→客户端 z 过滤；再不行→显示全图（现状）。

## 附录 C：待拍板问题（按"为什么定不了"分类拆解）

> 分类说明：**A 等实测** / **B 等勘察/评审** / **C 权衡验证** / **D 评审确认**。
> 每条格式：**问题 → 为什么现在定不了 → 怎么定（拍板条件）→ 当前默认值**。

### A 类：等实测

**A1. 二级楼层切分参数与 cf09301 的实际切分效果验证**（原 #3）—— ✅ **方法已验证（峰值/密度法）**
- 实测（2026-10-12，0.1m 直方图 + 峰值阈值 20% 最大 bin）：
  - cf09301：峰值楼层 z = **0.50 / 3.00**（主层 2.9~3.0；层高 **2.50m**）
  - cf09281658：峰值楼层 z = **-0.65 / 3.15 / 5.55**（层高 **3.80 / 2.40m**）
- 结论：**"z 间隙法"不可用**（楼梯把楼层连成连续带，两图都无 >1.5m 的 z 空隙）；**改用"峰值/密度法"切分**——`min_floor_gap_m` 废弃，改为 `hist_bin=0.1m + peak_threshold=20%`
- 备注：cf09301 主活动层在 **z≈2.9~3.0**（validate 佐证"原点地面 2.94"）；0.50 低区点占比约 7%——切分后需加"小面积层"判定（点数阈值），区分"独立楼层"与"下沉区/坡道"
- 默认值：hist_bin 0.1m、峰值阈值 20%

**A2. 高度窗口默认值是否按现场层高调整**（原 #4）—— ✅ **实测发现必须改**
- 实测层高：cf09301 **2.50m**、cf09281658 **3.80 / 2.40m**
- 结论：**默认 2.8m 会串层**（cf09301 层高 2.5m < 窗口 2.8m，上层地板会落进本层窗口）
- 改为自适应：`wall_height = story_height − 0.5m`（封顶 2.8m）；story 从 A1 的峰值法得出
- 默认值：自适应（story−0.5，cap 2.8）

**A3. 多层大图是否启用"块级分层"瓦片**（原 #2）—— ◐ **部分结论**
- 实测：30m 格下 cf09301 仅 5 块、cf09281658 9 块——块数少，混合块 + 客户端 z 过滤足够；**不启用块级分层**
- 保留：等真正多层大图（数十块 × 多层）再实测带宽/帧率复评
- 默认值：不启用

### B 类：等勘察/评审
