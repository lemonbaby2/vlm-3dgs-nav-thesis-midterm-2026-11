## 1. 背景与现状（代码级）

### 1.1 planner 现在怎么工作

```
启动：
  load_map(global_map.pcd)                     x_planner.cpp:5897、启动入口 :1194-1199
    ├─ 点云 → kdtree_（最近邻）                 x_planner.hpp:1536
    ├─ 点云 → Vox_map（体素哈希占用）           hpp:379-395、成员 :1604（res 0.2m，4~8 点/体素）
    ├─ 点云 → SDFMap2D（净空/代价）             hpp:1213（sdf_map_）
    ├─ 导航关键点 → kdtree_nav                  hpp:1244
    ├─ 拓扑图 → topology_nodes_/edges_/        hpp:1613-1616（rebuildTopologyGraph :1696）
    │           ground_clearance_/ground_risk_
    ├─ 语义地图（stairs）→ semantic_map_        semantic_map.hpp
    ├─ 楼层 → ground_levels_                    LoadGroundLevels :9962
    └─ ground_graph（可选，P0-2 新增）          诊断/兜底
全局规划：在 Vox/SDF/拓扑上做全局搜索 → global_path_ → 局部 ego 窗口避障执行
```

### 1.2 现状问题

| # | 问题 | 证据/影响 |
|---|---|---|
| 1 | 启动全量读 `global_map.pcd` 并建全部派生结构 | 大图启动慢、内存高（与主题二/三的加载问题同源） |
| 2 | 全局规划与全精度点云强绑定 | 其实全局只需要"能不能走"，不需要"墙上有几个点" |
| 3 | 跨层靠语义楼梯 + 楼层过滤，但无"轻量全局层"概念 | 没有楼梯语义的地图（如 cf09301 被拒）跨层退化 |
| 4 | 回环修图后派生结构失效无版本机制 | 闭环/合并后 planner 侧数据可能过期 |
| 5 | ground_graph 只做诊断/兜底 | 它其实是天然的"几何连接层"，可升格为常驻拓扑 |

### 1.3 导航的数据关系（近期讨论归纳）

**楼梯面与普通地面在点云里没有区别**——都是 "ground" 点，无编号无连接。连接由三层结构提供：

| 层 | 结构 | 连接机制 | 作用 |
|---|---|---|---|
| 几何 | `ground_graph`（已有 P0-2） | 半径连边（1m）+ **z 突变否决（0.35m）** | 台阶逐级连上、楼层间自动断开 |
| 语义 | `stair_patches.yaml` + `stair_graph.yaml` | patch 节点 + 显式边（`delta_z_m/gap/confidence`） | 跨层导航的正式路径（floor_0→t01…t16→floor_1） |
| 楼层 | `ground_levels` | z 聚类 + `stair_like` 标记 | 楼层归属与过滤（防穿楼板） |

点云与 patch 的关联是**空间匹配**（bbox + mean_z 查询），不是存储的点级链接。

## 2. 目标与不变量

### 2.1 目标

1. **全局导航成本与地图规模解耦**：启动只加载"全楼粗略能走图 + 楼梯连接 + 目标坐标"（几百 KB~几 MB）
2. **区域细图按需加载**：只加载"当前位置 + 前方走廊 + 目标附近"的高精度地图，用于局部安全与执行
3. **跨层能力保持**：stairs 语义 + ground_levels（含被拒场景的退化路径）
4. **地图一致性**：回环/合并后轻量层与细图按版本重建，不出现"粗图说能走、细图是墙"
5. **零回归**：开关关闭时与现状 planner 行为一致

### 2.2 不变量（评审重点）

- 全局规划**只依赖粗可通行表示**，不得回退到"必须全量点云"
- 粗图必须**保守**（不确定按障碍/高代价），细图加载后再做走廊修正
- 话题/接口不变：`/base_link/odom`、`/x_nav/current_pointcloud*`、规划结果发布不变
- 无轻量层产物时，自动回退现状全量加载（保底）

## 3. 概念梳理（导航相关，全景）

> 大白话解释见附录 A，这里先建立结构。

| 概念 | 一句话 | 本设计中的角色 |
|---|---|---|
| 全局规划 | 决定"从哪走到哪"的大方向 | 在粗图/拓扑上跑，轻量常驻 |
| 局部规划/避障 | 决定"如何安全地走好眼前几十米" | 用区域细图 + 实时障碍，现有逻辑不改 |
| Vox_map | 体素哈希占用图（有没有点） | 现状全局建；目标：区域化按需建 |
| SDFMap2D | 距离场（离障碍多远） | 现状全局建；目标：区域化 |
| 拓扑图 | 走廊节点+边的轻量图 | **升格为常驻全局层** |
| 粗栅格 | 0.3~0.5m 的每层占据/代价图 | **新增常驻全局层** |
| 净空/clearance | 可通行的宽度裕量 | 粗层用近似值；细层精确算 |
| ground_graph | 半径连边 + z 突变否决的几何连接 | 常驻几何连接层（已有实现） |
| patch/stair_graph | 可行走面片 + 语义边 | 跨层路由（已有） |
| ground_levels | 楼层高度层 | 楼层过滤（已有） |
| 回环检测 | 认出走过的路并纠正漂移 | 保证地图"闭合"，导航依赖；大地图要增强 |
| 描述子 | 关键帧指纹 | 回环（及自动重定位）的检索手段，与主题五共用 |
| 目标映射 | 目标点 → 层/格/拓扑节点 | 低成本的最后一段策略 |
| 版本（pose_version） | 地图内容版本 | 轻量层/细图/回环的一致性锚点 |

## 4. 设计 A：全局轻量层（finalize 烘焙 + 旧图 CLI 补算）

### 4.1 产物

```
<map>/
  nav_light/                        ← 新增目录（保存/finalize 时烘焙）
    index.json                      ← 版本、参数、统计
    floors/
      <level_id>/
        grid.bin                    ← 该层粗占据/代价栅格（定长二进制）
        meta.json                   ← 原点、分辨率、尺寸、z 基准、来源
        topology.json               ← 该层拓扑节点/边（可选，已有 rebuildTopologyGraph 输出）
    stairs.json                     ← 语义楼梯 + ground_levels 摘要（引用 stairs/ 原文件）
```

`nav_light/index.json`（建议）：

```json
{
  "version": 1,
  "map_id": "cf09301",
  "source_pose_version": 1,
  "grid_resolution": 0.5,
  "floors": [
    {"level_id": 0, "z_median": 2.851, "z_range": [2.55, 3.15],
     "grid": "floors/0/grid.bin",
     "meta": "floors/0/meta.json",
     "topology": "floors/0/topology.json",
     "cell_counts": {"free": 15234, "occupied": 3120, "unknown": 810}}
  ],
  "stairs_ref": "../stairs/stair_graph.yaml",
  "ground_levels_ref": "../ground_levels.json",
  "generated_at": "2026-10-10T18:00:00"
}
```

### 4.2 栅格生成规则（保守优先）

| 源数据 | 规则 |
|---|---|
| `global_ground_map.pcd`（地面） | 落在 z 窗口内的地面点 → `free` |
| `global_map.pcd`（障碍体） | **实现（2026-10-14）**：仅**无地面格**按带内点数阈值（≥3，带 [z_floor+0.25, z_floor+2.0]）→ `occupied`；膨胀只扩 unknown（"信任地面柱"口径） |
| 无数据区域 | `unknown`（按高代价处理，规划宁可绕） |
| 净空 | 粗层用"到最近障碍的格数 × 分辨率"近似（上限截断）；细层再精确算 |

- **地面格优先**：机器人实际走过的地面格保持 `free`（surf 不再覆盖地面格，规避“地面格全被占”问题；低矮障碍由实时避障层兜底）
- 单遍流式处理（逐帧或逐块读，内存峰值 = 单块 + 栅格）
- 大小估算：100m×100m @0.5m = 4 万格/层；10 层 ≈ 40 万格 ≈ **400KB**（1 字节/格 + 头）；即使 1M 格也只有 1MB

### 4.3 生成方式

1. **finalize 烘焙（主路径，C++）**：主题一 finalize 从全量数据烘焙 `nav_light/`（主题一 §4.15）；主题三 merge 后走统一重烘焙流水线
2. **旧图补算**：C++ CLI `semantic_tool bake-nav --map-dir ... [--grid 0.5] --write`
3. 版本联动：`source_pose_version` 与 `keyframe_index.json` 对齐；地图变化 +1 → 消费者拒绝不一致版本

## 5. 设计 B：planner 启动与全局规划改造

### 5.1 启动流程（目标态）

```
读 nav_light/index.json
  ├─ 各层 grid.bin → 常驻粗代价图（内存 ~MB 级）
  ├─ floors/*/topology.json → 常驻拓扑图（节点/边）
  ├─ stairs/ + ground_levels → 语义与楼层（现有 LoadSemanticNav/LoadGroundLevels）
  └─ nav_points → 目标映射
跳过 global_map.pcd 全量读；Vox_map/kdtree_/sdf_map_ 改建为"区域对象"（按需）
```

### 5.2 全局规划流水线

```
目标点 (x,y,z,floor)
 → 目标映射：所在层 → 粗栅格格子 / 最近拓扑节点
 → 楼层内：粗栅格 A*（或拓扑 Dijkstra，已有 topology_dijkstra 诊断可参考）
 → 跨层：semantic patch sequence（floor_0 → … → floor_1）
 → 产出"走廊路径"（粗路径 + 楼梯段）
 → 区域细图加载（沿走廊预取）
 → 细层修正：在细图上检查走廊可达性/净空 → 必要时局部绕行或重规划
 → 交给现有局部执行（ego 窗口 + 动态障碍）
```

### 5.3 区域细图加载（与主题二衔接）

- 加载单元：**chunk**（主题二 `chunks/index.json`）
- 触发：当前位置 + 沿粗路径前方 `lookahead`（建议 50~100m）+ 目标附近
- 使用：在其上建区域 `Vox_map`/`kdtree_`/`SDFMap2D`（或复用现有构建代码，限定点集）
- 淘汰：LRU（按区域距离/使用时间）；走出走廊段即释放
- 预取：粗路径下一段（避免转弯处空窗）
- 失败降级：细图读取超时/缺失 → 使用粗图 + 实时障碍继续，必要时减速（安全优先）

### 5.4 目标与最后一段

- 目标先映射到"层 + 粗格"；最后 `final_approach_m`（建议 20m）加载目标区域细图精化
- 目标是导航点时直接查导航点表（已有 `kdtree_nav`）
- 目标层判定：`ground_levels`/`levels` 匹配；跨层目标自动拼接楼梯段

### 5.5 一致性

- `nav_light`、`chunks`、`levels` 同用 `source_pose_version`；不一致 → 拒绝加载并提示重建
- 闭环/合并后：`derived_map_dirty` 标记 → 后台重烘焙 → planner 热更新（或提示重启加载）

## 6. 设计 C：局部执行与安全（基本不变）

- 现有局部执行链路（`egoReferenceWindow`、避免路径、动态障碍层）**不改逻辑**，只换数据来源（区域细图）
- 区域边界跨越：进入新 chunk 时增量更新区域 Vox/SDF（拼接）
- 安全兜底：
  - 粗图 `unknown` 不进规划
  - 细图发现粗路径不可通行 → 立即停/减速 + 局部重规划走廊段
  - 动态障碍仍走现有 dynamic layer

## 7. 设计 D：大地图回环检测（地图一致性保障）

> 导航依赖"闭合"的地图；地图裂了，全局路径就穿墙/绕远。回环检测分两层：

### 7.1 现状

- 建图模式 1Hz 线程（`loopClosureFrequency: 1`）：
  - 位姿 3m 半径找历史候选（`historyKeyframeSearchRadius: 3`，排除最近帧；localization 模式限定已加载帧）
  - 当前/历史各拼 10 帧子图（`historyKeyframeSearchNum: 10`）→ ICP → `fitness < 0.3` 接受
  - 接受后：between 约束入 GTSAM → 全局优化 → 重建局部匹配索引（地图重建）
- 跨图回环已存在（inter-map overlap，主题三）

### 7.2 大地图问题

1. **3m 半径依赖位姿**：漂移 > 3m 时永远检测不到（地图越大漂移越大）
2. 相似环境误检；多层相似可能串层
3. K 大后优化与重烘焙变贵

### 7.3 增强方案（两层回环）

| 层 | 手段 | 范围 |
|---|---|---|
| 短程（保留） | 位姿半径 + ICP | 小漂移、原地附近 |
| **长程（新增）** | **描述子检索**（复用主题五 Scan Context，finalize 预计算）+ ICP 验证 | 漂移几米~几十米、跨区域、跨层 |

防误检：
- 多帧一致性（连续 3~5 帧指向同一候选才接受）
- 描述子距离 + ICP fitness 双门
- 楼层约束（ground_levels；跨层必须经 stairs 合法）

成本控制：
- ISAM2 增量优化（现有）+ 回环最小间隔（冷却）
- 候选子图降采样后 ICP
- 闭环后：按 Spec 重建局部 IVox（唯一硬例外）；`nav_light`/`chunks`/派生图标 dirty **后台重烘焙**（主题一）
- 描述子只在触发时检索（O(K)，K 小；K 大时 ring key KD-Tree）

### 7.4 对导航的交付

- 闭环修正后地图"闭合"，全局粗图/拓扑随之重建（版本 +1）
- planner 检测版本变化 → 重载轻量层（或等待下次任务开始）

### 7.5 patch 与回环的关系（引入 patch 后是否要改算法）

**结论：检测骨架不变**——"找候选 → ICP 验证 → GTSAM 修正"这条主线保持；patch 是加在**验证/约束层**的语义增强，不是另一种回环算法。原因：patch 只覆盖**可行走面**（楼板/踏面/楼梯口），不覆盖墙面、天花板、家具，不足以单独判定"同一处"。

patch 带来三件事：

| # | 作用 | 说明 | 数据依赖 |
|---|---|---|---|
| ① 楼层护栏（防串层） | 回环候选必须**同层**，或经 `stair_graph` 合法连通；拒绝"同 (x,y) 不同 z"的假匹配 | 相似楼层是最大误检来源；仅用 `ground_levels` 也能做，patch/stair 让它更精确 | ground_levels（必须）；stair_graph（增强） |
| ② 楼梯区特判（步级一致性） | 楼梯踏面"每级长得几乎一样"（高差约 0.17m、重复纹理），ICP 容易**对错级**；用 patch 的 `step_index/mean_z` 校验：匹配前后高差应为**整级数**、不跳级、`entry/exit` 必须成对 | 楼梯回环（上下楼后绕回）常见且高危 | stair_patches/graph（`reviewed=true` 才用） |
| ③ 跨会话语义锚点 | 两图都有 `stair_A` 时，"同一部楼梯"是高置信度重访证据；供跨图回环（inter-map）、主题三合并（z/yaw 锚点）使用 | 同图内 patch_id 会话间会重生成，价值主要在跨会话/跨图 | 语义关系表（主题三） |

**现实限制（很重要）**：patch 是**保存后由工具链生成、并经质量门（自动几何门 + 放行策略）判定**的（cf09301 现状就是被质检拒绝、`reviewed=false`）。因此：

- **同会话在线回环不能依赖 patch** → 只能"有则用、无则退化"：退化为"纯几何 ICP + `ground_levels` 楼层约束"
- patch 真正发挥价值的场景：跨会话/跨图回环、离线合并、历史地图语义审计

**落地阶段**（与第 8 章改造清单对应）：

| 阶段 | 加什么 |
|---|---|
| P0 | 回环候选加"同层/合法楼层"硬约束（用 ground_levels 即可，不依赖 patch） |
| P1 | 楼梯区回环加"步级一致性校验"（dz 为整级数、不跳级、entry/exit 配对）；有 patch 才启用 |
| P2 | 长程/跨会话回环引入 patch 语义锚点与关系表（与主题三共用，A9/A10） |

## 附录 A：导航概念详解

### A1. 全局规划 vs 局部规划
- **全局**：回答"从 A 到 B 的大方向走法"（哪条走廊、哪部楼梯）。
- **局部**：回答"眼前这几十米怎么安全地走"（避障、贴边、速度）。
- **本设计角色**：全局层轻量化常驻，局部层按需加载细图——各司其职，成本分开算。

### A2. 可通行表示
- **是什么**：描述"哪里能走"的数据结构总称（占用栅格、体素、距离场、拓扑图）。
- **为什么**：规划本质是在可通行空间里找路径。
- **本设计角色**：粗表示常驻、细表示按需，是低成本全局导航的核心思想。

### A3. Vox_map（体素占用图）
- **是什么**：把空间切成小立方体记录"有没有点/是否占据"（planner 现用 0.2m 体素）。
- **为什么**：快速判断某处是否可通行。
- **本设计角色**：从"全局一份"改为"区域一份"，按需构建。

### A4. SDF / 净空（clearance）
- **是什么**：SDF 是每个位置到最近障碍的距离场；净空就是"还能过多宽"。
- **为什么**：让路径不贴墙、留安全边距。
- **本设计角色**：粗层用格数近似，细层精确计算（区域化）。

### A5. 拓扑图
- **是什么**：把可通行空间抽象成"节点（路口/房间）+ 边（连通关系）"的轻量图。
- **为什么**：几千节点就能代表一栋楼，搜索极快，适合常驻。
- **本设计角色**：全局规划的常驻层之一（与粗栅格二选一/互补）。

### A6. 粗栅格
- **是什么**：低分辨率（0.5m 左右）的占据/代价栅格。
- **为什么**：比点云小两三个数量级，却足够做"大方向"规划。
- **本设计角色**：新增的常驻全局层核心产物（`nav_light`）。

### A7. ground_graph（几何连接层）
- **是什么**：节点=地面采样点；边=半径 1m 内邻居，但 **z 差超 0.35m 不连**。
- **为什么**：不需要语义就能把台阶逐级连通、把楼层断开，天然防穿层。
- **本设计角色**：可升格为常驻几何拓扑/兜底层。

### A8. patch / stair_graph（语义连接）
- **是什么**：可行走面片（楼板/踏面/入口/出口）+ 面片之间的显式边（含高差/间隙/置信度）。
- **为什么**：跨层导航必须有"从哪上楼、上几级"的明确路线。
- **本设计角色**：全局规划跨层的正式路径；缺失时退化用几何层 + floor z 判断。

### A9. ground_levels（楼层）
- **是什么**：z 聚类出的楼层（高度、范围、是否含楼梯）。
- **本设计角色**：楼层过滤与目标映射的基准。

### A10. 回环检测
- **是什么**：认出"这地方我来过"，用匹配约束把累积漂移纠正回去，让地图闭合。
- **为什么**：地图不闭合，全局路径会绕远或穿墙；大地图必须做。
- **本设计角色**：短程（位姿半径）+ 长程（描述子）两层；闭环后触发轻量层重建。

### A11. 描述子（Scan Context 等）
- **是什么**：一帧扫描的"指纹"，用于快速检索相似位置。
- **本设计角色**：长程回环的候选生成；与主题五（自动重定位）共用同一份产物。

### A12. 目标映射 / 最后一段
- **是什么**：把目标点换算成"哪层、哪个粗格/节点"，最后临近时再加载高清细图精化。
- **为什么**：避免为"走到终点前 5 米"提前加载整片高清。
- **本设计角色**：区域加载触发策略的一部分。

### A13. 版本（source_pose_version）
- **是什么**：地图内容的版本号；闭环/合并/编辑会 +1。
- **为什么**：轻量层、瓦片、细图必须来自同一版本，否则几何对不上。
- **本设计角色**：一致性校验与失效重建的锚点。

## 附录 D：patch 的定义及生成流程（简要）

> patch（楼梯/楼板语义面片）不是手工画的；现行链路是**地图保存后由 Python 工具链生成**（见 D.2），经质量门控决定 `reviewed`，不达标则回退/被拒。**C++ 化与在线草稿方案见主题一 §4.13**：建图中产出 `*.draft`、finalize 权威定稿，算法逻辑与现有 Python 版保持一致；本附录描述的是现行生成流程。

### D.1 patch 的定义

- **是什么**：一条"可行走面片"的**语义元数据记录**——描述"这里有一块可以踩的面"，**不是点云**（不存任何点）
- **数据结构**（权威定义 `x_planner_v2/include/semantic_map.hpp:44-84`）：

```cpp
struct SemanticPatch {
    std::string patch_id;      // 唯一编号，如 floor_0 / stair_A_t03
    SurfaceType type;          // floor / stair_entry / tread / landing / stair_exit
    std::string floor_id;      // 属于哪层（楼板/楼梯口）
    std::string stair_id;      // 属于哪部楼梯
    std::string flight_id;     // 哪段梯段
    int step_index = -1;       // 第几级踏面（1..N）
    double mean_z = 0.0;       // 面片平均高度（楼层高度/踏面高度）
    bool has_bbox; double min_x, min_y, max_x, max_y;  // 水平范围
    bool has_z_range; double z_min, z_max;  // 可选：带坡度楼板
    bool reviewed = false;     // 复核/放行标志（自动几何门+放行策略；未放行 planner 默认不用）
};
// 边：id / type(floor_transition/step_transition/landing_transition) / from / to
//     / delta_z_m / horizontal_gap_m / confidence
// 楼梯图：stair_id / from_floor_id / to_floor_id / nodes[patch_id] / edges[]
```

**元数据字段明细（每个 patch 记录的完整内容）**：

| 字段 | 类型 | 含义 | cf09301 示例 |
|---|---|---|---|
| `patch_id` | string | 面片唯一编号（图内唯一） | `floor_0`、`stair_A_t03` |
| `type` | enum | 面片类型（决定其余字段是否有效） | `floor` / `stair_entry` / `tread` / `landing` / `stair_exit` |
| `floor_id` | string | 所属楼层（楼板=自身；入口=出发层；出口=到达层） | `floor_0`、`floor_1` |
| `stair_id` | string | 所属楼梯 | `stair_A` |
| `flight_id` | string | 所属梯段 | `stair_A_f1` |
| `step_index` | int | 踏面级号，从 1 起连续编号（仅 tread） | `1`~`16` |
| `mean_z` | double | 面片平均高度（map 系，米） | `2.851`（floor_0）、`5.595`（floor_1） |
| `bbox` | 4×double | 水平范围 `[min_x, min_y, max_x, max_y]`（map 系，米） | `[-3.93, -6.60, 7.42, 8.00]` |
| `z_min` / `z_max` | double? | 可选：带坡度楼板的 z 区间（平地不用） | — |
| `reviewed` | bool | 复核/放行标志（自动几何门 + 放行策略；planner 采用门槛） | `false`（cf09301） |

按类型看生效字段：

| type | 有效字段组合 |
|---|---|
| `floor` | `floor_id` + `mean_z` + `bbox`（+可选 `z_min/z_max`） |
| `stair_entry` | `stair_id` + `floor_id`（出发层）+ `mean_z` + `bbox` |
| `tread` | `stair_id` + `flight_id` + `step_index` + `mean_z` + `bbox` |
| `stair_exit` | `stair_id` + `floor_id`（到达层）+ `mean_z` + `bbox` |
| `landing` | `stair_id`（+`floor_id`）+ `mean_z` + `bbox` |

> patch 记录里**没有**：点数/点集、生成参数、时间戳（这些在 `stair_quality.json` / `stair_meta.json`）；跨层路由用的"关系边"单独存在 `stair_graph.yaml`（边字段：`id / type / from / to / bidirectional / delta_z_m / horizontal_gap_m / confidence`）。

- **落盘**（三个文件，原子写）：
  - `stairs/stair_patches.yaml`：`patches[]`（上面的字段，type 决定哪些字段有效）
  - `stairs/stair_graph.yaml`：`stairs[]`（节点 + 边；floor_0 → floor_1 的跨层关系）
  - `stairs/stair_quality.json`：质检报告（`reviewed / issues / measured_widths / source`）
- **patch 与点云的关系（重点）**：

```text
生成期（点云 → patch，只发生一次）：
  global_ground_map.pcd / ground/<i>.pcd（点云：只有坐标+强度，无编号）
        │  stair_map.py 测量：z±0.05 内的点投影到轨迹 → 得出高度/宽度/范围
        ▼
  stair_patches.yaml（元数据：bbox + mean_z + 语义编号 + 关系边）

使用期（patch → 点集，查询时现算，不落盘）：
  点属于某 patch 的判定 = 水平落在 bbox 内 且 |z − mean_z| < 容差
  容差：生成时 Z_TOL_M=0.05m；planner 校验 patch_height_tolerance=0.06m
```

| 关系维度 | 说明 |
|---|---|
| 点云存什么 | 只有坐标 + 强度；**没有任何 patch 编号或语义标签** |
| patch 存什么 | 只有上面字段表里的元数据（编号/类型/楼层归属/高度/范围/复核标志）；**不存点，也不持有"我的点云文件"** |
| 唯一关联方式 | **空间匹配（bbox + z 容差）**，谁都不引用谁；同一个点可能同时落入多个 patch 的候选范围，靠 z 容差与优先级消歧 |
| 生成方向 | 点云是 patch 的**几何来源**（宽度/高度/范围全部从点云实测，轨迹负责分级定位）；patch 是点云的"摘要 + 语义" |
| 查询方向 | patch 是"筛子"：按 bbox+z 从点云筛出"某级踏面/某块楼板的点"，供楼层切分（主题四）、回环校验（§7.5）、前端高亮使用 |
| 能力边界 | patch 是 2.5D 面，只能做 bbox + z 窗口过滤，处理不了悬挑/夹层；墙面、天花板、障碍点不属于任何 patch |
| 现状提醒 | cf09301 的 patch 被拒（`trajectory_fallback`）→ 这条关联链在 planner 侧不生效，全链路退化为 `ground_levels` 的 z 过滤 |
- **类型范围**：只覆盖"地面类"可行走面（楼板/踏面/平台/楼梯口），不含墙面、障碍、天花板
- **消费方**：planner 跨层语义路由（`FindSemanticPatchSequence`）、质检/工具链、前端楼层图层（主题四）；SLAM 建图/定位不使用

### D.2 工具与触发

| 环节 | 位置 | 说明 |
|---|---|---|
| 草稿生成 | `stair_draft.py`（`build_draft:751`） | 由点云平面聚类或建图轨迹分析出楼板/踏面/entry/exit 候选（`reviewed=false`） |
| 精确化 + 质检 + 门控 | `stair_map.py`（`generate_stair_map:582`、`validate_and_gate:307`、纯轨迹回退 `build_trajectory_fallback:380`） | 轨迹锚定每级踏面、点云实测宽度、质量校验 |
| 触发方式 | web 层保存地图后**异步**调用：`extra.py:703 → _ensure_stair_draft:1990 → stair_map.ensure_stair_draft` | 默认只生成草稿（`write=False/reviewed_auto=False`），**不覆盖已有 stairs** |
| 离线修正 | `tools/stair_traverse/rebuild_stair_patches.py` | 重测踏面宽度、替换旋转矩形 bbox（保留其他字段） |

输入数据：`global_map.pcd`（测宽）+ `poses_base.txt`（上行轨迹）+ `ground_levels`（floor patch 来源）+ `stair_meta.json`（可选，踏步高参考）。

### D.3 生成流程（六步）

```
① 草稿：平面聚类（z 分箱）或轨迹分段 → 楼板/踏面/入口/出口候选
② ROI：非 floor patch 的范围外扩 1.5m → 楼梯区域
③ 上行 pass：ROI 内轨迹按 z 升序、y 基本单调（容差 0.6m）→ 中线折线 + 弧长
④ 逐级测量：踏面高度 z±0.05 的点投影到 pass → 弧长定位该级；
           横向聚类实测宽度（80 分位）；同时算轨迹偏置
⑤ 锚点与 bbox：锚点弧长单调化并逐级铺开 → 旋转矩形 bbox；
               entry/exit 锚在梯段两端（带偏移）
⑥ 质检门控（validate_and_gate）：
   级数 ≥3、step_index 连续、bbox 合法、
   踏面测量覆盖率 ≥50%、宽度 p80 ≥0.6m、
   级高 0.08~0.24m、多层不重叠、轨迹偏置 ≤0.25m
   → 全过则 reviewed=true；否则 reviewed=false 并写 issues
```

### D.4 回退与门控结果

| 情况 | 结果 | 标记 |
|---|---|---|
| 踏面拟合达标 | 正常 patch + 图，`reviewed=true` | — |
| 踏面拟合失败 | **纯轨迹回退**：级数 = 爬高阶差 / 参考踏步高（0.17m，夹紧 0.12~0.22）；锚点均匀铺在轨迹上；宽度默认 1.0m；进深 = 爬升水平长 / 级数 | `source: trajectory_fallback`（**cf09301 现状**） |
| 质检有阻断项 | 输出但不复核，planner 默认不采用（`require_reviewed`） | `stair_quality.json` 的 `issues` |
| 现场决定不用 | 归档为 `stairs.rejected-<date>/`（如 cf09301 的 `stairs.rejected-anchor-20261009`） | — |

> `reviewed` 的产生方式（口径统一）：**自动几何门 + 放行策略**——CLI/工具默认"自动门过即 `reviewed=true`"；线上保存路径稳妥起见强制 `reviewed=false`，等人工/抽查放行（详见主题一 §4.13）。"全部 rejected 归档"是**放行策略的保守选择**，不是"没有自动化"。

输出（原子写）：`stairs/stair_patches.yaml` + `stairs/stair_graph.yaml` + `stairs/stair_quality.json`。

### D.5 与导航的关系

- `floor` patch 提供楼层平面范围与高度（与 `ground_levels` 对齐）；`stair_graph` 的边提供跨层路由
- `reviewed=false` 或缺失 → planner/前端全链路走 `ground_levels` 退化路径（本设计所有方案都保留该降级）
- patch 仅在**保存后**生成 → 在线建图期的回环检测不能依赖它（见 §7.5）

## 附录 E：跨 patch 导航的实现（现状）

> 说明"从一层走到另一层"当前是怎么实现的：语义 patch 图做跨层路由，逐踏面锚点做执行，楼梯护航区做感知/控制适配。不走语义时完全退化为普通导航（零回归）。

### E.1 总览：三条协作链

| 链 | 作用 | 算法/机制 |
|---|---|---|
| 普通导航（单层） | 层内从 A 到 B | 拓扑图 **Dijkstra** 全局路径 + 局部 **A*** 避障 + Odom PID 跟踪（§4~§6） |
| **跨层语义导航** | 决定"走哪部楼梯、经过哪些踏面" | **patch 图显式边最短路**（`FindSemanticPatchSequence`）+ **逐踏面锚点队列** + **逐边执行状态机**（`StairExecutionManager`） |
| 楼梯护航区适配 | 楼梯上安全地走 | 低层点障碍过滤 + 走廊居中 + 双侧净空降速 |

三条链通过开关并存：`enable_semantic_nav_`、`enable_stair_execution_`（默认关）；不开时行为与旧版一致。

### E.2 加载期准备（建图后、planner 启动时）

```
LoadSemanticNav（x_planner.cpp:10059）
  ├─ 读 stairs/stair_patches.yaml + stair_graph.yaml
  ├─ 校验（require_reviewed / 单级高度 / 边置信度…）→ 失败则整体不可用（降级普通导航）
  ├─ BuildStairCorridorMap（:10474）：按 stair_id 聚合 entry/tread/exit，
  │    PCA 主轴 → 楼梯走廊中线锚点（含各级半宽）
  └─ AssignKeypointsToPatches（:10096）：导航关键点按 bbox+z 容差归属到 patch
        （z 先减去 global_path_height_offset_ 还原地面高度；取 dz 最小、面积最小者）
```

`keypoint_patch_` 让拓扑图/Dijkstra 具备"patch 感知"：起点关键点选择会优先与机器人同 patch（`:4209-4233`），跨 patch 的拓扑边有特殊处理（`:3571-3590`）。

### E.3 规划期：跨层判定与语义最短路

入口：`buildMultiNavQueue`（`:2439`）——单目标 + 语义开关打开时走跨层分支（`:2452-2593`）：

```
① 当前 patch：RobotPatch()（:10403）= 当前位姿 x,y + (z − base_link高度) 做归属解析
② 目标 patch：ResolvePatchForPose(target.x, target.y, target.z − base_link高度)
   → 归属歧义（多个候选 z 差在 margin 内）直接拒绝：START_SURFACE_AMBIGUOUS
③ 若 robot_patch == target_patch → 不跨层，走普通导航
④ 否则：FindSemanticPatchSequence(robot_patch → target_patch)（semantic_map.cpp:1246）
     在 patch 图上跑优先队列 Dijkstra（只用合法楼梯的边）：
       边权 = max(0.05, horizontal_gap) + |Δz| + 0.5(若 step_transition) + (1−confidence)
     失败 → GOAL_PATCH_NOT_FOUND / CROSS_FLOOR_ROUTE_NOT_FOUND
⑤ 生成锚点序列：
     - 中间锚点优先用"楼梯走廊中线锚点"（居中走）
     - 无走廊数据时退化为 FindKeypointForPatch（导航关键点）兜底
     - 末锚点 = 真实目标点
⑥ 展开为 multi_nav 队列（逐锚点下发）+ StairExecutionManager.Start(patches, anchors)
     → stair_route_active_ = true
```

每个锚点的 z 会加 `base_link_height_m_`（转成机器人参照高度），中间锚点朝向保持原样、只对末点使用目标朝向。

### E.4 执行期：逐边状态机与安全门

执行在每个 Odom 控制周期进行（`callbackFromCurrentPose`）：

```
定位同步门（:6370-6384）：
  Odom 与雷达时间差超限 → localization_valid=false、不发速度；
  若楼梯正在执行 → 直接 StopStairExecution(STAIR_LOCALIZATION_LOST)

逐边看护 TickStairExecution（:10621）→ StairExecutionManager.Update：
  robot_patch = RobotPatch()（含歧义检测）
  ├─ has_pose=false            → 停：STAIR_LOCALIZATION_LOST
  ├─ 单步超时（默认 30s）       → 停：STAIR_STEP_FEEDBACK_TIMEOUT
  ├─ patch 意外跳变（既不是当前/上一/下一目标，且序位超前） → 停：STAIR_UNEXPECTED_PATCH_TRANSITION
  └─ 正常 → 继续等待到达

到达推进 MarkReached（必须有归属证据）：
  robot_patch == 当前期望 patch 才允许推进 step_index；
  否则停：STAIR_UNEXPECTED_PATCH_TRANSITION（"到达无证据"）
  推进到最后一步 → kFinished，楼梯段结束，接回普通导航/下一个目标
```

重新规划不破坏锚点（N5）：每次重规划后 `SemanticPathAnchorsPreserved`（`:10418`）校验路径仍**按顺序经过当前段锚点**（插值/B 样条不得删除踏面锚点）；违反 → `STAIR_ANCHOR_SKIPPED` + 停止（`:2423-2431`）。

停止统一走 `StopStairExecution`（`:10448`）：停车 + 清空路径/队列 + `has_goal_=false` + 状态码 15。

### E.5 楼梯护航区的感知/控制适配

`StairGuardActive`（`:10462`）= 正在执行楼梯路线，或机器人当前 patch 非 floor（entry/tread/landing/exit）。护航区内：

| 适配 | 内容 | 位置 |
|---|---|---|
| 局部障碍过滤 | **台阶/踢面等低层点不进入局部障碍**（否则整段楼梯被膨胀成"墙"，局部 A* 全判碰撞）；栏杆/墙由净空兜底 | `:7343-7362`（`stair_local_filter`） |
| 走廊居中 | 路径点横向投影到楼梯中线（限制单点最大平移量） | `stair_corridor.hpp:RecenterPointToCorridor`、`:7423` |
| 双侧净空降速 | base 系前向窗口内双侧最近净空 < 慢速阈值（默认 0.35m）→ 速度缩放 | `EvaluateStairClearance`、`:7422-7441` |

速度输出仍走原来的 `refresh_path → 前视点 → PID → TRACK/AVOID/REACH → /cmd_vel`，楼梯适配只影响"障碍解释"和"速度缩放"。

### E.6 失败码与处理汇总

| 阶段 | 失败码 | 含义 | 处理 |
|---|---|---|---|
| 加载/校验 | `SEMANTIC_MAP_NOT_FOUND` / `MAP_REVISION_MISMATCH` / `STAIR_GRAPH_NOT_REVIEWED` / `STAIR_GRAPH_INVALID_EDGE` / `STAIR_GRAPH_NON_CONSECUTIVE_STEP` / `STAIR_GRAPH_LANDING_BYPASS` | 语义图缺失/未复核/边非法/跳级 | 语义不可用 → 退化普通导航 |
| 规划 | `GOAL_PATCH_NOT_FOUND` / `CROSS_FLOOR_ROUTE_NOT_FOUND` / `START_SURFACE_AMBIGUOUS` / `SEMANTIC_ROUTE_KEYPOINT_MISSING` | 目标无 patch / 图不连通 / 起终点归属歧义 / 锚点关键点缺失 | 拒绝任务并返回原因 |
| 执行 | `STAIR_UNEXPECTED_PATCH_TRANSITION` / `STAIR_STEP_FEEDBACK_TIMEOUT` / `STAIR_LOCALIZATION_LOST` / `STAIR_ANCHOR_SKIPPED` / `STAIR_OPERATOR_TAKEOVER_REQUIRED` | 走错面片 / 单步超时 / 定位丢失 / 锚点被删 / 需人工接管 | 立即停车、清路径、报状态 |

### E.7 与普通导航、降级路径的关系

- **单层目标**（robot_patch == target_patch，或语义开关关闭、语义图不可用）：完全走原链路（拓扑 Dijkstra + 局部 A* + PID），零回归
- **跨层目标**：语义路线接管为"多段队列"——每个踏面锚点是一次短目标，逐段刷新/PID 跟踪，段间由逐边状态机看护
- **语义被拒/缺失**（cf09301 现状：patch 在 `stairs.rejected-*`、`reviewed=false`）→ `LoadSemanticMap` 返回不可用 → 跨层分支不进入 → 退化为普通导航 + `ground_levels` 楼层过滤（跨层将不可达或需人工分段导航）
- **兜底几何连接**（ground_graph，P0-2，默认关）：提供"台阶逐级连通、楼层断开"的几何拓扑，可作为无 patch 场景的规划兜底，不参与逐边执行
