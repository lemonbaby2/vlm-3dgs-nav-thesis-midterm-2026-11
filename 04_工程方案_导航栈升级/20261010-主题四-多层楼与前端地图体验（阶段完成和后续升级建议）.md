## 一、本插件（`navigation-mapping`）的升级点

### 1.1 背景：补齐"插件缺楼层/小地图"的缺口

此前仓库内主题四实现位于 `code/web_app/src`（`floorManager` / `floorPreviewLayer` / `FloorSwitcher` / `miniMap`），而现场真正使用的 UI 是 App 插件 `plugins-dev/navigation-mapping`。本次把上述能力**移植进插件**并适配插件的网络与构建约束。

### 1.2 新增文件（插件 `frontend/src`）

| 文件 | 作用 |
|---|---|
| `constants/levels.ts` | 楼层模式开关（`use_floor_mode`）、`FLOOR_CONFIG`；非当前层显示方式（`floor_others_mode`：`hidden`/`faded`） |
| `constants/minimap.ts` | 小地图开关（`minimap_enable`）、`MINIMAP_CONFIG`（尺寸/颜色/视口框颜色等） |
| `services/levels/floorManager.ts` | 拉取 `levels/index.json`（JSON 走插件代理）；按 `(x,y)` 加载**楼层预览 PCD** 与**楼梯过渡层 PCD**（**直连机器人 :9000**）；inflight 去重 + 世代号防串图 |
| `services/levels/floorPreviewLayer.ts` | `Three.js` 楼层预览层：当前层正常、其余层按模式**隐藏/虚化**；楼梯过渡层常显；切层只改 `visible/opacity`，不重建场景、不触发 `switch_map` |
| `services/minimap/miniMap.ts` | 独立小画布（正交俯视）+ 机器人箭头 + **主视口覆盖框**；支持与主视口**同步旋转** |
| `components/FloorSwitcher.tsx` | 楼层切换面板：Lx·z、机器人所在层标记、跟随开关、"其他楼层：虚化/隐藏"切换 |

### 1.3 修改文件（插件）

- `hooks/useThreeScene.ts`：初始化/挂载楼层层与小地图；动画循环内注入机器人位姿、楼层跟随、小地图同步旋转与视口框；地图切换时刷新；卸载时释放。
- `pages/index/NewIndexPage.tsx`：消费 hook 新增状态，渲染 `FloorSwitcher` 与小地图容器；透传 `minimapContainerRef`。
- `layouts/Sidebar/SettingsPanel.tsx`："可视化控制"页新增两个开关：**楼层模式（按层显示）**、**全局小地图**（写 localStorage，点"刷新页面生效"后应用）。
- `manifest.json`：版本升至 **1.1.17**。

### 1.4 关键行为与默认值

- **默认关**：`use_floor_mode=0`、`minimap_enable=0`；关闭时与现状完全一致（零回归）。
- **数据源**：
  - 楼层索引：`GET /api/extra/get_levels`（经插件代理，JSON）。
  - 楼层预览 / 楼梯过渡层：`GET /levels/<map>/<id>/preview_downsize.pcd`、`GET /levels/<map>/stairs_<id>.pcd`（**直连机器人 :9000**；插件代理只回传 JSON，二进制会 502）。
  - 小地图：`GET /api/extra/get_map_l2`（`global_map_downsize.pcd`，压缩全图点云）。
- **楼层显示**：点击某层 → 该层正常；其余层：
  - `faded`（默认）：全部半透明显示（`FLOOR_CONFIG.othersOpacity = 0.18`）；
  - `hidden`：完全不显示。
  - 切换入口：楼层切换面板里的 **"其他楼层：虚化/隐藏"**（记忆于 `floor_others_mode`）。
- **楼梯过渡层**：`stairs_<id>.pcd` 常显（归相邻层）。
- **小地图**：
  - 背景深色、点云为压缩灰度（数据本身即灰度，所以看着"灰"）；
  - **与主视口同步旋转**：按主相机方位角旋转俯视相机 `up`，使主视口"前方"在小地图中朝上；
  - **蓝色覆盖框**：标出主视口当前看到的地面范围，随主相机位置/朝向/远近实时更新；
  - 红色箭头显示机器人真实朝向（相对当前视图）。
- **切换地图**：楼层/小地图自动 `refresh` 新地图；无 `levels` 产物时楼层列表为空、UI 自动隐藏（降级）。

### 1.5 构建、部署与验证

- 校验：`npm run type-check` **0 错误**；`npm run build:plugin` 通过（bundle 约 938KB，仅体积告警）。
- 部署：App 插件 **v1.1.17** 已上线；catalog 日志 `Loaded plugin: navigation-mapping (v1.1.17)`。
- 部署经验（重要，避免踩坑）：
  1. 主机按 manifest 的 `bundle` / `frontend.bundle` **原样加载** → 部署时**必须改成实际带时间戳的文件名**（不能留 `navigation-mapping.umd.js` 通用名，否则 404）。
  2. manifest 必须是 **UTF-8 无 BOM**（带 BOM 会导致 catalog 报 `Unexpected UTF-8 BOM` 而加载失败）。
  3. 替换 bundle 时**先拷新、再删旧**，避免"文件短暂不存在"的窗口被浏览器撞上。
  4. `frontend/dist/` 被 `.gitignore` 忽略，产物不入库；靠 `build:plugin` 重新生成。

### 1.6 已知限制（阶段完成范围内）

- 小地图点云为**压缩灰度**（非彩色/纹理），视觉上偏灰。
- `faded` 模式需要加载"所有楼层"预览（小图无压力；大图需评估内存/耗时）。
- 楼层仍由自动算法（z 直方图/密度）切分，**尚无手工编辑**——"中间纯楼梯"这类结构无法靠自动结果表达（见第二部分）。
- 楼层/小地图均为**纯前端显示**，不影响导航；楼层判定与 planner 仍需保持同一数据口径（见后文建议）。

## 二、后续升级方案：楼层/楼梯"分段编辑器"

### 2.1 问题：自动分层切不出"纯楼梯"

自动分层（`ProductBaker::ComputeLevels`，z 直方图/密度）只切"水平层"，**无法把"楼梯过渡段"单独拎出**。实测表现：
- `cf0928`：被并成 **1 层**；
- `cf09211647`：被切成 **5 层**（偏碎）；
- 现场楼梯实际为 **3 段**（楼层—纯楼梯—楼层），自动结果与真实结构不符。

因此需要"可编辑的楼层/楼梯描述层"，而不是继续调自动参数。

### 2.2 三个概念必须分开

| 概念 | 含义 | 作用 |
|---|---|---|
| **楼层（floor）** | 近似水平的可走面（z 窗口 + 平面范围） | 楼层显示/切换、楼层过滤、目标映射 |
| **楼梯段（stair segment）** | 斜的、有台阶的过渡段，**不属于任何楼层** | 跨层连接、楼梯图层、合并/拆分对象 |
| **面片（patch）** | entry/tread/exit 等细粒度语义标注 | 楼梯执行、回环校验、高亮；**不是"段"** |

> 关键取舍：**展示用"垂直分段（segments）"，语义用 `type`（floor/stair）**。只有 `type=floor` 的段进入"楼层切换器"；`type=stair` 的段单列（可单独显隐/虚化），避免楼层与楼梯混并。

### 2.3 核心方案：编辑"描述层"，不动点云

新增一份**可编辑描述文件** `levels/edit.json`（segments model），**优先于自动结果**；删除即回到自动结果。

```jsonc
{
  "version": 2,
  "source_pose_version": 1,          // 与地图版本对齐，地图变化后需复核
  "segments": [
    {"id":"floor_0","type":"floor","z_min":-1.0,"z_max":0.4,"polygon":[...],"source":"manual"},
    {"id":"stair_A_1","type":"stair","stair_id":"stair_A",
     "z_min":0.4,"z_max":2.2,"bbox":[...],"source":"manual"},
    {"id":"floor_1","type":"floor","z_min":2.2,"z_max":3.6,"polygon":[...],"source":"manual"}
  ]
}
```

- **不破坏原始数据**：点云、patch 均不动，只改"分组/命名/类型"。
- **可重复编辑**：保存后按 segments 重算 `levels/<id>/preview_downsize.pcd` 与楼梯过渡层。
- **回退**：保留自动 `levels/index.json`；`edit.json` 失效/删除即回退。

### 2.4 操作定义（MVP 四项）

1. **合并（merge）**：把相邻同类型段并成一段（z_min 取小、z_max 取大；多边形取并集）。
2. **拆分（split）**：一段在某 z 处切两段（或按框选/多边形切范围）。
3. **改类型（relabel）**：把某段标为 `floor` 或 `stair`——**"中间纯楼梯"即用此项**。
4. **楼梯段拆分/合并**：把一条楼梯拆成 3 段（下平台/纯梯段/上平台），或把多段并回一条。

> 合并/拆分只作用于**同类型段**，避免"楼层与楼梯混并"。

### 2.5 如何"把楼梯区分出来"（由易到难）

1. **复用已有语义**：存在 `stairs/stair_graph.yaml` + `stair_patches.yaml` + `stairs_<id>.pcd` 时，直接把楼梯作为独立实体列出（如 cf09281658 的 `stair_A`）。
2. **几何自动识别**（无 patch 的图）：用地面点云沿 z 的**坡度/台阶周期性/净空**粗找斜段，给出候选，**人工确认/框选**。
3. **手工框选**：在 3D/俯视中框 **bbox + z 区间**，标为 `stair`（最稳的兜底）。
4. **段与 patch 解耦**：段是粗粒度（楼层/显示/规划用），patch 是细粒度（执行用）；二者通过 `stair_id` 关联，**不强制一一对应**——段可手工改，patch 仍由工具链生成。

### 2.6 工具形态与消费方

- **编辑器 UI**：列出所有段（z 范围/类型/点数/来源），支持选中 → 合并/拆分/改类型/画框；3D 中高亮该段点云（复用 `levels/<id>/preview` 与 `stairs_<id>.pcd`）。
- **保存**：原子写 `levels/edit.json`（含 `source_pose_version`），可选"立即重算预览"。
- **统一消费（关键）**：前端 `floorManager`、planner（楼层/目标判定）、`nav_light` 重烘焙**读取同一份 segments**，避免三处各算各的导致"显示层 ≠ 导航层"。
- **版本与回退**：`source_pose_version` 变化（回环/合并/重烘焙）时提示"基于旧版本，需复核"；删除 `edit.json` 回退自动结果。

### 2.7 风险与注意

- **一致性**：编辑后必须让 `ground_levels`、`nav_light` 层、前端楼层一致。
- **多边形 vs z 窗口**：先做 z 窗口（简单），再做多边形（处理挑空/夹层）。
- **别把 patch 当段**：patch 是踏面级，段是楼层级；强行一一对应会显著复杂化。
- **大图**：`faded` 全层加载 + 编辑重算预览需评估内存/耗时。

### 2.8 建议落地顺序（后续）

1. 定义 `levels/edit.json`（segments schema）与读取优先级（edit > auto）。
2. 编辑器 v1：**列表 + 合并/拆分 z 窗口 + 改类型（floor/stair）**，保存后重算预览。
3. 楼梯：先"复用现有 stair_graph/patch + 手工拆 3 段"，再补几何自动识别。
4. 一致性：`floorManager` / planner / `nav_light` 统一读 segments；版本校验 + 回退。
