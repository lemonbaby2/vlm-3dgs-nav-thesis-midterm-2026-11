## 1. 背景与现状（代码级）

### 1.1 已经有的能力（别重复造）

| 能力 | 实现 | 位置 |
|---|---|---|
| 手动初始位姿 | `/initialpose` 回调 → 种子位姿 → 定位初始化 | `InitialPoseCallBack:6398`、`InitialPoseCallBack_transformTobeMapped_imu_correct:6495` |
| 手动触发重定位 | slam 服务 `cmd=relocalization`：`hand_init_state=true` + 触发初始化 | `:6955-6968` |
| 多候选分阶段 GICP | 初始化阶段在种子附近多候选尝试匹配 | `ProcessLocalizationInitialization:5986`；开关 `relocalization_random_mode_=1`（`:1697`） |
| GPS 自动定位 | `auto_localization_enableflag`（默认 false）：GPS 时间同步检查 + 50m 内找最近关键帧 → 设种子 → 初始化 | `:4885-4970`（另两处同逻辑 `:5183/:5465`）；种子写入 `UpdateLocalizationSeedPose:5764` |
| 搜索半径参数 | `localization_search_radius: 4`（yaml:235）、失败扩大 `localization_search_radius_max`（yaml:238，P0-1 新增） | x_nav.yaml |
| 重定位关键帧插入 | handoff 时 `addRelocalizationKeyframe`（当前受门控，Spec 将无条件化） | `:12621`、门控 `:6305-6317` |
| 局部 GICP 目标构造 | `localization_local_map_`：以种子为圆心选邻近关键帧拼子图 | `ProcessLocalizationInitialization` 链路 |
| 自定义消息先例 | `x_nav/msg/Pose6D.msg`（已有 msg 通道） | `code/x_nav_mj/catkin_ws_src/x_nav/msg/` |

### 1.2 能力边界与缺口

- **已有"自动"只有 GPS 一种**：室内无 GPS 时，仍要人工给大致位置（App/手柄发 `/initialpose`）
- **无全局描述子**：仓库内没有任何 Scan Context 类检索（已核实），候选只能来自"种子附近"
- **多候选是"一次性阶段尝试"**：`relocalization_random_mode_` 在初始化阶段做多候选，但没有"跨帧存活、随运动收敛"的假设管理
- **无消歧交互**：前端无法看到"当前有几个候选、谁在胜出、该往哪走"
- **相似环境误匹配无兜底**：相似走廊/对称楼层可能直接错锁，且无"多帧一致性"校验

### 1.3 实例（测试基线）

- cf09301：170 关键帧、两层（floor_0 z≈2.85 / floor_1 z≈5.59），`ground_levels` 可约束楼层；楼梯被拒（见主题三）不影响本主题
- 相似楼层歧义是本项目最典型的"感知歧义"场景；多层图还有**串层**风险（同 (x,y) 不同 z）

## 2. 目标与不变量

### 2.1 目标

1. **L1**：finalize 预计算关键帧全局描述子（C++ 流水线）；运行时无先验给出 top-k 候选（含验证与楼层约束）
2. **L2**：多假设跨帧存活、权重随观测更新、运动辅助消歧；达到收敛判据才 handoff
3. **L3**：GPS/楼层选择/人工点选等外部线索只做兜底，不阻塞主流程
4. **前端引导**：状态、候选、置信度、建议动作全部可见、可操作、可人工兜底
5. **零回归**：功能关闭时，现有"人工种子 + 多候选 GICP"路径行为不变

### 2.2 不变量（评审重点）

- 未收敛前**不进入正常跟踪**（宁可慢，不可错锁）；导航任务在此阶段禁用
- 消歧期间机器人动作必须**安全受限**（限速、避障全开、优先原地旋转）
- 所有新状态经 `hand_init_state`/`UpdateLocalizationSeedPose`/`InitialPoseCallBack...` 现有入口进入，**不绕过现有初始化链**
- 收敛后 handoff 走现有 `addRelocalizationKeyframe` + Spec 无条件局部构建
- 假设状态仅存内存（不落盘），重启即重新开始

## 3. 概念速览（正文用到的角色）

| 概念 | 一句话 |
|---|---|
| 感知歧义 | 不同位置看起来一样，单帧无法分辨 |
| 全局重定位 | 没有初始位置提示，自己确定在地图哪里 |
| 描述子 | 一帧扫描的"指纹"，用于快速检索相似位置 |
| Scan Context | 一种常用点云描述子（按方位/距离切格子编码） |
| ring key | 描述子的"粗指纹"，先粗筛再精算，快 |
| 候选（candidate） | 检索出来的"可能位置"（一个关键帧位姿） |
| 假设（hypothesis） | 进入消歧的候选，带权重，跨帧存活 |
| 粒子滤波 / MCL | 用一堆带权重的假设表达"我可能在哪"的经典方法 |
| 权重 / 似然 | 假设与当前观测的吻合程度 |
| 收敛 | 一个假设明显胜出且稳定 |
| 主动重定位 | 特意做小动作（旋转/前进）来制造区分度 |
| handoff | 消歧结束，交给正常跟踪 |
| 重捕获 | 跟踪丢失后重新走一遍定位流程 |

## 4. 设计 A：L1 全局描述子检索

### 4.1 技术选型（建议）

| 方案 | 原理 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **Scan Context** | 极坐标格子（方位×距离）落点成 2D 图；列移位天然容忍 yaw；ring key 快速预筛 | 无需训练、实现简单、社区成熟、单帧毫秒级 | 对高度变化/空旷场景一般 | **推荐基线（P0）** |
| LiDAR-Iris | 极坐标+傅里叶编码 | 旋转/高度更稳 | 实现与调参更复杂 | P1 可替换验证 |
| M2DP | 双投影直方图 | 轻量 | 精度一般 | 备选 |
| 学习类（PointNetVLAD 等） | 网络嵌入 | 泛化/歧义场景更强 | 需训练数据/算力/部署 | 远期 |

**建议**：先用 Scan Context 把 L1→L2 链路跑通，选型留在配置后（`reloc_descriptor_type`）。

### 4.2 描述子产物（finalize 预计算）

**关键洞察**：描述子从**关键帧本体（传感器/机体坐标系）**计算，闭环优化只改全局位姿、不改本体点云 → **描述子不随位姿版本失效**；只有重扫/编辑改变了点云才需要重算。

新增产物：

```
<map>/
  descriptors/
    descriptors.bin        ← 每帧一个描述子（定长矩阵，按序号排布）
    descriptors_meta.json  ← 版本、参数、帧数、每帧偏移
```

`descriptors_meta.json`（建议）：

```json
{
  "version": 1,
  "map_id": "cf09301",
  "descriptor_type": "scan_context",
  "config": {"n_sectors": 60, "n_rings": 20, "max_radius": 80.0},
  "keyframe_count": 170,
  "frame_size_bytes": 4800,
  "created_at": "2026-10-10T16:00:00"
}
```

- 生成：**finalize 时自动**（C++，读 `surf/<i>.pcd` 计算）；旧图用 CLI 补（`semantic_tool descriptors`）
- 与主题二共存：都在 finalize 阶段产出，可合并为一个"产物烘焙"步骤

### 4.3 运行时检索流水线

```
① 粗筛（ring key）：当前帧 ring key 与全部关键帧 ring key 做 KNN（KD-Tree/暴力 O(K)，K 小）
    → 取前 N1（如 20）候选
② 精排（完整描述子距离）：逐对计算 SC 距离（列移位取最小）
    → 取前 K（如 5~8）候选
③ 几何验证（复用现有能力）：
    以候选位姿为种子构造局部子图（复用 localization_local_map_ 逻辑）
    → GICP 对齐当前帧 → fitness 打分
④ 楼层约束：候选 z（或 floor mean_z）必须落在当前可用楼层集合（ground_levels，可配置"全部/指定层"）
⑤ 输出：verified_candidates[] = {pose, descriptor_dist, gicp_fitness, score, floor_id}
```

- 得分建议：`score = w1 * (1 - norm(fitness)) + w2 * (1 - norm(descriptor_dist))`，权重可配
- **触发时机**：定位模式启动且无种子；跟踪丢失进入重捕获；手动 `reloc_start`

## 5. 设计 B：L2 多假设序列消歧

### 5.1 假设对象

```cpp
struct RelocHypothesis {
  uint64_t seed_keyframe_id;         // 来源关键帧（全局 id）
  Eigen::Affine3f pose;              // 当前估计位姿（map 系）
  float weight;                      // 归一化权重（0~1）
  float last_fitness;                // 最近一次 GICP fitness
  int age;                           // 存活帧数
  int consecutive_top;               // 连续成为 top1 的次数
  double last_update_stamp;
};
```

- 最大假设数 `reloc_max_hypotheses`（默认 8）
- 假设在进入消歧时由 L1 的 verified_candidates 初始化（低分候选可直接不进假设集）

### 5.2 状态机

```
UNLOCALIZED ──(启动/丢失)──► RETRIEVING ──(L1 出候选)──► DISAMBIGUATING
     ▲                                                       │
     │                                            (收敛判据满足)
     └──(重捕获 RTB)◄── TRACKING ◄──(handoff)── CONVERGED
```

| 状态 | 行为 | 对外输出 |
|---|---|---|
| `UNLOCALIZED` | 等触发（启动/手动/GPS/丢失） | 状态=未定位 |
| `RETRIEVING` | 跑 L1（1 次，几百 ms） | 候选列表（可选显示） |
| `DISAMBIGUATING` | 每帧更新假设、给出建议动作 | 假设列表 + 权重 + 建议 |
| `CONVERGED` | 锁定 top1，准备 handoff | 最优位姿 + 置信度 |
| `TRACKING` | 正常定位跟踪（现有） | 现有话题 |
| 重捕获 | 跟踪丢失 → `RETRIEVING`（跳过人工） | 状态流转日志 |

### 5.3 每帧更新（限流 2~5Hz）

```
对每个假设（按权重轮询取样，单帧最多验证 N=3 个）：
  1. 预测：用 odom/IMU 增量小步推进假设位姿（可选，先不做）
  2. 观测：以假设位姿构造局部子图（复用现有局部图逻辑）→ 与当前帧 GICP
  3. 更新：likelihood = exp(-k * fitness)；weight *= likelihood；归一化
  4. 淘汰：weight < prune_threshold（如 0.05）或 age 过大且 fitness 差 → 删除
  5. 空集处理：全灭 → 重新 L1 检索（限频，如 5s 一次）
收敛判据（全部满足）：
  a. top1 weight > converged_weight（如 0.8）
  b. top1 - top2 margin > margin_threshold（如 0.3）
  c. top1 连续 N 帧（如 5）第一
  d. top1 最近 3 次 GICP fitness < fitness_gate
  e. 与上一帧 top1 位姿跳变 < jump_gate
→ 进入 CONVERGED → handoff
```

### 5.4 运动策略与主动重定位

| 优先级 | 动作 | 说明 |
|---|---|---|
| 1 | **原地旋转 360°（分步，如每步 45°）** | 四足原地旋转最安全；每步后做一轮假设更新 |
| 2 | 短距离直行 1~3m（低速） | 走廊场景有效；需前方安全 |
| 3 | 主动选择动作（进阶，P3） | 对每个候选"预测下一步观测差异"，选区分度最大的动作（旋转角/方向） |

- 执行方式：默认**自动模式**（算法发动作，前端可随时暂停/接管）；也可纯手动（前端引导人推）
- 消歧期约束：限速（如 0.2m/s、0.3rad/s）、禁导航任务、避障全功率、**不允许快速长距离移动**
- 与导航栈关系：动作走底层速度接口/现有 joystick 通道，不进入 planner 任务流

### 5.5 与现有初始化链的衔接

```
收敛后：
  UpdateLocalizationSeedPose(top1.pose)                    （现有 :5764）
  → hand_init_state = true
  → InitialPoseCallBack_transformTobeMapped_imu_correct()  （现有 :6495）
  → ProcessLocalizationInitialization                      （现有 :5986，多候选 GICP 作为最终确认）
  → 成功：addRelocalizationKeyframe（Spec 无条件局部构建）  （:12621 / :6305）
  → TRACKING
```

- **复用点**：多候选 GICP 是天然的"最终验证器"；不需要另写配准
- **handoff 失败**：回到 `DISAMBIGUATING`，把失败候选权重惩罚，继续消歧

### 5.6 计算预算

| 环节 | 频率 | 成本控制 |
|---|---|---|
| L1 检索 | 触发时 1 次 | ring key 预筛 + K 小 |
| 描述子精排 | 触发时 1 次 | O(N1·L)（N1≈20） |
| 假设 GICP 验证 | 2~5Hz，每轮 ≤3 个 | 子图小（半径/点数上限）、限流 |
| 假设管理 | 每帧 | O(H)，H≤8，忽略不计 |

目标：消歧期 CPU 增量 ≤ 15%（单核，待标定）。

## 6. 设计 C：L3 外部线索兜底

| 线索 | 现状 | 本设计用法 |
|---|---|---|
| GPS | **已实现**（`auto_localization_enableflag`） | 保留为最高优先外部线索（室外） |
| 楼层选择 | 前端可按 levels/ground_levels 选层 | 把"当前楼层集合"喂给 L1 的楼层约束（大幅降歧义） |
| 人工点选 | `/initialpose` 已有 | 前端小地图点选 → 直接给种子（最快兜底） |
| UWB/二维码/反光柱 | 无 | 远期接入，接口同"种子位姿" |

优先级链：**外部线索（GPS/人工）→ L1+L2 自动 → 超时再回外部线索**。任何一级可用都能收敛，互不阻塞。

## 7. 设计 D：前端引导设计

### 7.1 状态展示区（常驻）

| 元素 | 说明 |
|---|---|
| 大字状态 | `未定位 / 检索中 / 消歧中（N 个候选）/ 定位成功 / 跟踪丢失` |
| 置信度条 | top1 weight |
| 犹豫度 | top1−top2 分差（可视化"还有多不确定"） |
| 楼层提示 | 当前候选集中在哪些楼层（跨层歧义时高亮） |
| 导航按钮 | 未收敛时置灰 + 提示"定位完成后可用" |

### 7.2 候选可视化（消歧的核心画面）

- 每个假设画一个**半透明幽灵机器人**（箭头/小模型），透明度 = 权重
- top1 高亮（如描边/更亮颜色），标注 `1号 62% / 2号 28%`
- 消歧中随权重变化动态淡入淡出；收敛时只剩一个 → 给操作者强烈的"确定感"
- 选项：显示候选的"视线连线"（当前扫描特征到候选位置的对应关系，调试用）

### 7.3 动作引导区

| 控件 | 行为 |
|---|---|
| `原地旋转一圈（推荐）` | 自动分步旋转，实时显示进度（135°/360°） |
| `向前直行 2 米` | 低速短距离动作 |
| `暂停/继续消歧` | 停止动作，保留假设 |
| `自动模式开关` | 默认开；关掉后由操作者手动推 |
| 收敛进度 | "已连续 3/5 帧稳定"等文字提示 |

### 7.4 人工兜底区

- 小地图（主题四）点击"楼层 + 大致区域" → 生成种子位姿 → 调 `set_initial_pose`（等价 `relocalization` 服务）
- "定位不对"按钮：回 `RETRIEVING` 并预置"人工给的区域"缩小检索范围

### 7.5 安全与防呆

- 消歧动作中显示限速状态与周围障碍（复用现有显示）
- `reloc_timeout`（建议 30s）未收敛 → 自动停止动作 → 提示人工兜底
- 误收敛防护：收敛后先"软确认"（1~2s 内跟踪误差达标）再解锁导航
- 全程操作日志（状态切换/动作/收敛耗时）便于复盘

## 8. 接口与话题

### 8.1 状态话题（新增）

建议自定义消息（仓库已有 `Pose6D.msg` 先例）：

```
# x_nav/msg/RelocalizationState.msg（建议）
std_msgs/Header header
uint8 STATE_UNLOCALIZED=0
uint8 STATE_RETRIEVING=1
uint8 STATE_DISAMBIGUATING=2
uint8 STATE_CONVERGED=3
uint8 STATE_TRACKING=4
uint8 state
float32 top_weight
float32 margin
uint8 suggested_action          # 0=none 1=rotate 2=advance 3=stop
float32 action_progress          # 0~1
RelocHypothesis[] hypotheses     # 位姿/权重/编号
uint64[] hypothesis_ids
```

- 话题名 `/x_nav/relocalization/state`，1~5Hz（限流）
- 备选：JSON 字符串（`std_msgs/String`）先落地，稳定后换自定义消息（**待定**）

### 8.2 命令（扩展现有 slam 服务）

在现有 `CallbackFrom_slam_service` 白名单（`:6889+`）新增：

| cmd | 行为 |
|---|---|
| `reloc_start` | 启动消歧（可带楼层/区域参数） |
| `reloc_rotate` / `reloc_advance` | 执行指定引导动作 |
| `reloc_pause` / `reloc_confirm` / `reloc_reject` | 暂停/确认/否定当前假设 |
| `set_initial_pose`（已有 `/initialpose` 可替代） | 人工种子 |

Web 层（`extra.py`）做同名 HTTP 转发；前端调用现有命令通道。

### 8.3 产物/检索接口

- `descriptors/`（地图目录内）——finalize 产出（C++）；旧图用 `semantic_tool descriptors` 补算
- 可选：`get_reloc_candidates?map=`（调试用，返回最近一次 L1 结果）

## 9. 参数设计（yaml，默认关闭）

| 参数 | 建议默认 | 说明 |
|---|---|---|

## 附录 A：专业名词详解

> 按"是什么 → 为什么 → 在本方案中的角色"三段式。

### A1. 全局重定位（Global Localization）
- **是什么**：不给初始位置提示，机器人自己确定"我在地图的哪里"。
- **为什么难**：配准算法是局部优化，起点太远会配错；环境相似时单帧本身就有多解。
- **本方案角色**：L1+L2 要解决的总体问题。

### A2. 感知歧义（Perceptual Aliasing）
- **是什么**：不同位置看起来几乎一样（相似走廊、对称货架、上下层相似布局），单帧观测无法区分。
- **为什么**：这是"无先验重定位"的根本困难，不是算法实现问题。
- **本方案角色**：L2 多假设消歧与楼层约束就是为了化解它。

### A3. 描述子（Descriptor）/ 全局描述子
- **是什么**：把一帧扫描压成一个定长的"指纹"向量/矩阵，相似场景指纹相似。
- **为什么**：用于快速检索"地图里哪些关键帧跟当前帧像"，避免全图暴力匹配。
- **本方案角色**：L1 的检索依据；finalize 预计算（C++），运行时比对。

### A4. Scan Context
- **是什么**：把水平面按"方位角×距离"切成格子，每格取最高点，形成 2D 图；比较时允许列循环移位（容忍旋转）。
- **为什么**：无需训练、实现简单、速度快，是 LiDAR 场景识别的经典基线。
- **本方案角色**：推荐首选的描述子类型（`reloc_descriptor_type` 可替换）。

### A5. ring key
- **是什么**：Scan Context 按"距离环"做统计得到的低维向量（丢掉了方位信息）。
- **为什么**：先用它粗筛（快），再对少量候选算完整描述子距离（准）——两级检索。
- **本方案角色**：L1 第一步粗筛（N1≈20）。

### A6. 候选（Candidate）
- **是什么**：检索出的"可能位置"，每个是一个关键帧位姿（或位姿+分数）。
- **为什么**：候选是消歧的输入，不是结论。
- **本方案角色**：L1 输出 top-k；通过几何验证后进入 L2 假设集。

### A7. 假设（Hypothesis）
- **是什么**："机器人可能在某处"的一个具体猜测，带位姿、权重、存活时间。
- **为什么**：单帧无法排除歧义，就把多个猜测都留着，用后续观测逐步淘汰。
- **本方案角色**：L2 的核心数据结构。

### A8. 粒子滤波 / MCL（蒙特卡洛定位）
- **是什么**：用一大群带权重的"猜测粒子"表示位置分布；每步"预测（运动）→ 更新（观测打分）→ 重采样（优胜劣汰）"。
- **为什么**：经典解决全局定位/绑架恢复的框架。
- **本方案角色**：L2 的工程简化版——粒子数很少（≤8）、以关键帧为骨架、用 GICP 打分。

### A9. 似然 / 权重
- **似然**：某个假设"能多好地解释当前观测"（这里用 GICP fitness 转换）。
- **权重**：所有假设归一化后的相对可信度（总和为 1）。
- **本方案角色**：权重决定前端透明度、淘汰顺序与收敛判定。

### A10. 收敛判据
- **是什么**：判定"消歧结束"的一组条件：top1 权重够高、领先第二名够多、连续稳定多帧、fitness 够好、位姿不跳变。
- **为什么**：只看一帧容易误判；多条件联合把误锁概率压到可接受。
- **本方案角色**：`CONVERGED` 状态的门槛（第 5.3 节 a~e）。

### A11. 主动重定位（Active Relocalization）
- **是什么**：机器人不是被动等待，而是主动做小动作（原地旋转、短直行）来获取"有区分度"的观测。
- **为什么**：歧义环境下站着不动永远分不清；动起来才能制造差异。
- **本方案角色**：L2 的运动策略（先旋转后直行），四足平台优先最安全的原地旋转。

### A12. handoff（交接）
- **是什么**：消歧结束后，把估计位姿交给正常跟踪链路（进入持续定位）。
- **为什么**：消歧和跟踪是两套逻辑，需要明确的切换点与状态初始化。
- **本方案角色**：复用现有 `UpdateLocalizationSeedPose` → `InitialPoseCallBack...` → `ProcessLocalizationInitialization` 链。

### A13. 重捕获（Re-acquisition）
- **是什么**：正常跟踪丢失后，重新走"检索→消歧"流程找回来。
- **为什么**：被抬起/打滑/长时间遮挡后需要恢复，不必重启系统。
- **本方案角色**：`TRACKING → RETRIEVING` 的自动回流。

### A14. GICP 验证
- **是什么**：用 GICP 把当前帧与"候选位姿处的局部子图"对齐，用 fitness 判断这个候选是否真的成立。
- **为什么**：描述子只保证"像"，几何配准才证明"就是这里"（且能给出精确位姿）。
- **本方案角色**：候选验证器 + 最终定位器，复用现有子图与多候选 GICP 能力。

### A15. fitness score
- **是什么**：配准残差类指标，越小越吻合。
- **本方案角色**：假设似然、收敛判据、验证门槛都用它（阈值需实测标定）。

### A16. 软确认
- **是什么**：收敛后不立刻解锁导航，先让跟踪跑 1~2 秒，确认误差持续达标。
- **为什么**：防止"错锁后立刻自驾"这类最危险的失败。
- **本方案角色**：`CONVERGED → TRACKING` 之间的安全闸。
