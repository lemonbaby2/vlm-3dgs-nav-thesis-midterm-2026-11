## 三、核心数字（口径务必看清）

### 表 A　本机双卡 · 3 种子均值（2500 迭代 / 5000 点 / 12 帧 160×120）

| 配置 | PSNR 全图 | PSNR 静态区 | PSNR 动态区 | SSIM | 动态残影 |
|---|---:|---:|---:|---:|---:|
| A 朴素全图 | 22.607 ± 0.199 | 30.990 ± 0.630 | 10.298 ± 0.217 | 0.908 | 0.0831 ± 0.0064 |
| B 动态掩码加权 | 21.111 ± 0.012 | **34.425 ± 0.090** | 8.296 ± 0.004 | **0.919** | **0.0049 ± 0.0001** |
| C 仅初始化滤波 | 22.532 ± 0.012 | 31.294 ± 0.723 | 10.256 ± 0.138 | 0.909 | 0.0768 ± 0.0053 |

- 静态区 **B − A = +3.43 dB**；残影 **16.9×**
- **B 的全图 PSNR 最低，但静态区最高** —— 这是设计使然：它主动放弃拟合动态像素。判据必须看静态区与残影，不能看全图 PSNR

### 表 B　DGX 放大版 · 3 种子均值（250 迭代 / 8000 点 / 24 帧 320×240）

| 配置 | PSNR 静态区 | 动态残影 |
|---|---:|---:|
| A 朴素全图 | 21.820 ± 0.148 | 0.1335 ± 0.0024 |
| B 动态掩码加权 | **30.071 ± 0.026** | **0.0082 ± 0.0003** |
| C 仅初始化滤波 | 29.578 ± 0.113 | 0.0139 ± 0.0005 |

- 静态区 **B − A = +8.25 dB**（小场景只有 +3.43），残影 **16.3×**
- 说明：**收益随场景复杂度上升而放大，不是小数据欠拟合的产物**

### 表 C　一项如实披露的失败判据

小场景下「C 残影 > B 的 5 倍」成立（15.7×）；**放大场景只有 1.70×，不成立**。原因是点数增至 8000 后，仅靠初始化滤波已足够稀薄，掩码加权的增量优势被压缩。这条已写进报告与 PPT 备注，不做修饰。

## 四、必须防的三个误读

1. **本包 PSNR 与论文 SOTA 不可直接比较**。这里是解析合成场景（12 帧 / 160×120 / 5000 点），论文多在 Replica / TUM / 官方 Lego 全分辨率上跑。它是**机制对照验证**，不是复现 SOTA。
2. **两套体系不能混**。本课题这批（+3.43 dB / 16.9×）与 SourceAware 论文那批（+4.03 dB / 7.5×）是不同场景、不同实现，各有各的口径。
3. **DTU 那条 34.42 dB 是"静态区"不是"全图"**。全图只有 21.11 dB，因为动态像素被主动放弃。

## 五、怎么复跑

```bash
# 1) 单轮全量（3 种子 × 3 配置，双卡并行，约 70 分钟）
cd 05_脚本_可复跑
python daily_verify.py --force --seeds 0,1,2 --iters 2500 --points 5000

# 2) 只重出报表（读已有 runs 目录）
python daily_verify.py --date 2026-11-17 --report-only

# 3) 重绘本包三张 PPT 配图
python make_figs.py

# 4) 把图贴回开题 PPT（会先替换 P13/P16 图，再给 P17 加图）
python insert_figs.py
python add_render_page.py
```

`daily_verify.py` 默认带 **GPU 门控**：只有利用率 ≤20% 且空闲显存 ≥55% 的卡才参与，两块都忙就自动跳过并写 `_skip.md`。这是设计意图，不要用 `--force` 绕过。

## 六、渲染图怎么看

`03_实验图像可视化/fig_repro_render.png` 是 4 行 × 3 帧：

| 行 | 内容 |
|---|---|
| 1 | 真值 GT |
| 2 | C 仅静态帧训练 |

看第 6 帧与第 11 帧：A 在球经过的位置留下橙色斑，C 也留、略轻，**B 的位置是干净的**。三组用完全相同的点数、迭代数、分辨率，唯一差别是损失函数是否按掩码加权。残影不是分辨率问题，是"动态像素被当作静态结构参与优化"的问题。
